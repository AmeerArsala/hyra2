# Init — Vault Scaffold

## Purpose

Create a new LLM Wiki vault from scratch with one command. Works the same in every harness.

## Inputs (ask the user)

- `vault_name` (kebab-case slug)
- `vault_path` (absolute path on disk; must be empty or not exist yet)
- Optional: domain seed list

## Outputs

```
$vault_path/
├── wiki.config.md           # schema_version: 0.4.0
├── AGENTS.md                # vault instructions for any agent (Codex, OpenCode, Antigravity, Pi, ...)
├── CLAUDE.md                # imports AGENTS.md for Claude Code
├── index.md                 # created and regenerated by update-index.sh
├── .gitignore  .obsidian/
├── raw/{external,internal}/
└── wiki/
    ├── hot.md
    ├── _drafts/  contradictions/  _logs/
    ├── concepts/  entities/  decisions/  comparisons/
    ├── synthesis/  sources/  open-questions/
```

## Workflow

1. **Ask the user** for vault_name and vault_path.
2. **Validate** the target path is empty or doesn't exist.
3. **Run** `$WIKI_SKILL/scripts/new-vault.sh --name $vault_name --path $vault_path`
   (it writes the config, runs `init-vault.sh`, and seeds AGENTS.md/CLAUDE.md).
4. **Print quick-start**:
   ```
   Vault scaffolded at $vault_path

   Quick start:
   - Open $vault_path in Obsidian (optional; it is plain markdown)
   - First research: "research <topic>"      (researcher role)
   - First capture: "save this URL/PDF/text" (scribe role)
   - Status anytime: $WIKI_SKILL/scripts/wiki-stats.sh --vault $vault_path
   ```

## Quality gate

- `wiki.config.md` has `vault_path` and `schema_version: 0.4.0`.
- `wiki/hot.md` exists and `.git` was initialised in the vault.
- Re-running on an existing vault must fail with "already initialized", never overwrite.

## Scripts used

- `$WIKI_SKILL/scripts/new-vault.sh` (wraps `init-vault.sh`)
